# 여행 계획표 웹 뷰어 MVP PRD

## 🎯 핵심 정보

**목적**: 여행 플래너가 노션에 입력한 여행 계획표를 클라이언트가 링크 하나로 웹에서 확인하고 PDF로 내려받게 해, 문서 수작업 전달을 없앤다.
**사용자**: 여행사·개인 여행 플래너에게 일정을 받는 고객(별도 회원가입 없이 공유 링크로 접속하는 클라이언트)

## 🚶 사용자 여정

```
0. [플래너] 노션 '여행' 데이터베이스에 여행 계획 + 일정 입력
   ↓ 상태를 '발행'으로 변경 후 공유 링크 전달

1. [클라이언트] 공유 링크 클릭
   ↓ 링크의 공유 토큰 유효성 검사

   [토큰 유효 + 발행 상태] → 여행 계획표 페이지
   [토큰 불일치 / 미발행] → 접근 불가 페이지 (종료)
   ↓

2. 여행 계획표 페이지
   ↓ 여행 개요 확인 → Day별 일정 확인
   ↓ [PDF 다운로드] 버튼 클릭

3. PDF 생성 및 다운로드
   ↓ 성공 → 파일 저장 / 실패 → 토스트 에러 후 재시도

4. [완료] → 페이지에서 계속 열람 또는 종료
```

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F001** | 여행 개요 표시 | 여행 제목, 고객명, 목적지, 여행 기간, 총 일수, 플래너 메모 표시 | 클라이언트가 가장 먼저 확인하는 핵심 정보 | 여행 계획표 페이지 |
| **F002** | Day별 일정 표시 | 일정 항목을 날짜(Day 1, Day 2…)로 묶고 시간순 정렬해 시간·장소·활동·메모를 표시 | 여행 계획표의 본문, 서비스 핵심 가치 | 여행 계획표 페이지 |
| **F003** | PDF 다운로드 | 화면과 동일한 구성(개요 + Day별 일정)의 A4 PDF를 서버에서 생성(링크 검증 재수행), 한글 폰트 임베드, `여행제목_시작일.pdf`로 저장(파일명 특수문자 제거, UTF-8 인코딩) | 오프라인 보관·인쇄 요구 충족 | 여행 계획표 페이지 |

### 2. MVP 필수 지원 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F010** | 공유 링크 접근 제어 | 플래너가 노션에 입력한 랜덤 공유 토큰(`shareToken`)으로만 접근, '발행' 상태만 노출, 토큰 불일치·미발행·미존재는 동일한 접근 불가 처리. 링크 폐기는 노션에서 토큰 값을 변경해 수행 | 로그인 없이 해당 고객에게만 계획표 공개, 노션 내부 ID 노출 방지 | 여행 계획표 페이지, 접근 불가 페이지 |
| **F011** | 노션 데이터 연동 | 노션 API(버전 2025-09-03, 데이터 소스 기준)로 여행·일정을 조회해 화면용 데이터로 변환. 100건 초과 시 페이지네이션, 429 응답 시 `Retry-After` 재시도, 캐시 재검증 60~300초, 노션 장애 시 직전 캐시 표시. 이미지·첨부파일은 MVP에서 제외 | 플래너가 노션 입력만으로 내용 갱신 | 여행 계획표 페이지 |

> 인증(회원가입/로그인)은 제외: 플래너는 노션에서 입력하고, 클라이언트는 공유 링크로만 접근하므로 계정이 필요 없음.

### 3. MVP 이후 기능 (제외)

- 클라이언트 로그인 및 내 여행 목록
- 웹에서 일정 편집·코멘트·승인 기능
- 지도 연동, 날씨·환율 정보
- 다국어 PDF, PDF 디자인 테마 선택
- 이메일/카카오톡 자동 발송
- 링크 만료·비밀번호 보호

## 🗄️ 데이터 모델

데이터 원본은 노션 데이터베이스 2개이며, 앱은 읽기 전용으로 조회한다. 노션 API 2025-09-03 기준으로 조회 대상은 각 데이터베이스의 `data_source_id`이며, 환경변수로 여행·일정 데이터 소스 ID를 각각 관리한다. 두 데이터베이스는 노션 Integration에 공유(Add connections)되어 있어야 한다.

### Trip (노션 '여행' 데이터베이스)
| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | 노션 페이지 ID (내부 식별용, URL에 노출하지 않음) | string |
| shareToken | 공유 링크 식별자 (랜덤 값, 변경 시 기존 링크 폐기) | Rich text |
| title | 여행 제목 | Title |
| clientName | 고객명 | Rich text |
| destination | 목적지 | Rich text |
| period | 여행 기간 (시작일~종료일) | Date (range) |
| status | 공개 상태 (초안/발행) | Select |
| note | 플래너 메모 | Rich text |

### ItineraryItem (노션 '일정' 데이터베이스)
| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | 노션 페이지 ID | string |
| trip | 소속 여행 | → Trip.id (Relation) |
| date | 일정 날짜 (Day 계산 기준) | Date |
| time | 시작 시간 (`HH:mm` 형식, 형식 오류·빈 값은 해당 날짜 하단에 표시) | Rich text |
| place | 장소 | Title |
| activity | 활동 내용 | Rich text |
| memo | 비고 (예약번호, 준비물 등) | Rich text |

> 데이터 규칙: 여행 기간 밖의 일정 날짜는 표시에서 제외, 스키마 검증(Zod) 실패 항목은 건너뛰고 나머지를 표시, 이미지·첨부파일은 MVP 제외.

## 🛠️ 기술 스택 (최신 버전)

### 🎨 프론트엔드 프레임워크

- **Next.js 15.5.3** (App Router + Turbopack) - 서버 컴포넌트에서 노션 데이터 조회, ISR 재검증
- **React 19.1** - UI 라이브러리
- **TypeScript 5** - 노션 응답 → 도메인 타입 변환의 안전성 확보

### 🎨 스타일링 & UI

- **TailwindCSS v4** (설정파일 없는 새로운 엔진) - 유틸리티 CSS
- **shadcn/ui** (new-york) - Card, Badge, Button, Separator, Skeleton
- **Lucide React** - 아이콘
- **Sonner** - PDF 생성 실패 토스트

### 📄 PDF 생성

- **@react-pdf/renderer 4.1+** (React 19 지원 버전) - 서버에서 PDF 생성, `next.config`의 `serverExternalPackages`에 등록
- **한글 폰트**: Pretendard 또는 Noto Sans KR의 정적 TTF(굵기별)를 프로젝트에 포함해 등록
- **첫 작업(스파이크)**: 한글 샘플 PDF로 폰트 등록·줄바꿈·Turbopack 빌드 동작 확인

### 🗄️ 데이터 소스 & 검증

- **Notion API 2025-09-03** + **@notionhq/client ^5** (최신 5.x) - 데이터 소스 쿼리로 여행·일정 조회 (CMS 역할)
- **Node.js 22 이상** - `@notionhq/client` 최신 버전 요구사항 (`@types/node`도 22로 상향)
- **Zod 4** - 노션 응답 데이터 파싱·검증

### 🚀 배포 & 호스팅

- **Vercel** - Next.js 배포, 환경변수(`NOTION_API_KEY`, DB ID) 관리

### 📦 패키지 관리

- **npm** - 의존성 관리
